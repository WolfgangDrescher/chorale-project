A reference takes a value from the score instead of writing it into the query:

- `"@2"`, `"@below"`: what [another voice](#another-voice) sounds at the same time.
- `"#1"`, `"$<name>"`: what the score has at an [earlier position](#an-earlier-position) of the match,
  by its number or by a [name](#naming-a-position) you give it.

`"@lower"` and `"@upper"` in [`voices`](/docs/query-schema) and the key `hint-@pair` are no
references: they name the voices of the pair a query over voice pairs searches.

## Another voice

Under `kern`, `kern.pitch` and `duration`, and under no other key, a value can name another
voice: `"@2"` stands for what voice 2 sounds at the same time. As a plain value it asks for
the same, as the `value` of a [comparison](/docs/patterns#comparisons) for higher, lower, longer
or shorter.

The tenor on the pitch of the soprano, a unison:

```json
{
    "feature": "kern",
    "voices": "tenor",
    "pattern": [{ "kern.pitch": "@4" }]
}
```

`{ "kern": "@4" }` also asks for the same note duration: a tenor quarter under a soprano half note
does not match it.

With [`kernIgnoreOctave`](/docs/options#kernignoreoctave) the register does not count. The tenor
doubles the soprano at a fermata, in unison or an octave or two below:

```json
{
    "feature": "kern",
    "voices": "tenor",
    "pattern": [{ "kern.pitch": "@4", "fermata": true }],
    "kernIgnoreOctave": true
}
```

The note duration works the same way. Two tenor notes as long as the soprano notes sung with
them, the second with a fermata:

```json
{
    "feature": "kern",
    "voices": "tenor",
    "pattern": [{ "duration": "@4" }, { "duration": "@4", "fermata": true }]
}
```

With a comparison under `kern`, the pitch of the searched voice is compared with the pitch of the
other voice, without the duration. The alto above the soprano:

```json
{
    "feature": "kern",
    "voices": "alto",
    "pattern": [{ "kern": { "operator": "gt", "value": "@4" } }]
}
```

This finds only the places where the alto starts a note above the soprano, not those where the
soprano moves below a held note of the alto, see [Which voice is searched](#which-voice-is-searched).

| Reference                    | Stands for                                              |
|------------------------------|---------------------------------------------------------|
| `"@1"` … `"@4"`              | that voice (1 is the bass, 4 the soprano)               |
| `"@below"`, `"@above"`       | the neighbour voice below or above the one searched     |
| `"@anyBelow"`, `"@anyAbove"` | any of the voices below or above: one of them is enough |
| `"@allBelow"`, `"@allAbove"` | all of the voices below or above                        |
| `"@anyOther"`, `"@allOther"` | any, or all, of the other three voices                  |

A voice crossing, in all voices at once:

```json
{
    "feature": "kern",
    "voices": "all",
    "pattern": [{ "kern": { "operator": "lt", "value": "@anyBelow" } }]
}
```

### Details

- The other voice counts with the note it sounds at that moment, also one it started earlier.
- `duration` reads tied notes as one note.
- A rest is no note: nothing is higher, lower or the same. A negated reference (`!kern`)
  therefore matches where one of the two voices rests.
- A voice is never its own reference: `"@below"` of the bass matches nothing. Several references
  in a list are an OR; for all of them, use an `@all…` reference.
- A negated `duration` reference cannot be combined with
  [`durationAllowSplitNotes`](/docs/options#durationallowsplitnotes) or
  [`durationAllowMergedNotes`](/docs/options#durationallowmergednotes).

### Which voice is searched

A voice reference is checked only where the searched voice starts a note. Where the other voice
moves while the searched voice holds its note, nothing is checked. So two queries can ask the
same question and still find different places, because the voices start their notes at
different times. Both of these look for a voice below the bass:

```json
{
    "feature": "kern",
    "voices": "234",
    "pattern": [{ "kern": { "operator": "lt", "value": "@1" } }]
}
```

```json
{
    "feature": "kern",
    "voices": "1",
    "pattern": [{ "kern": { "operator": "gt", "value": "@anyAbove" } }]
}
```

- The first finds the notes of tenor, alto and soprano that start below the bass: the upper
  voice moves. The result is a note of voice 2, 3 or 4.
- The second finds the bass notes that start above at least one upper voice: the bass moves.
  The result is a bass note, and it does not say which voice it crossed.

In chor005 a voice sounds below the bass at three moments, and each query sees only some of
them:

| Where                            | What happens                                          | First query | Second query |
|----------------------------------|-------------------------------------------------------|:-----------:|:------------:|
| measure 8, last eighth           | the bass moves up to A over the held G of the tenor   |             |      ✔       |
| measure 9, first beat            | the bass moves to B, the tenor to G, at the same time |      ✔      |      ✔       |
| measure 9, second half of beat 3 | the tenor moves to B below the held C of the bass     |      ✔      |              |

Both queries in one array find all three:

```json
[
    {
        "feature": "kern",
        "voices": "234",
        "pattern": [{ "kern": { "operator": "lt", "value": "@1" } }]
    },
    {
        "feature": "kern",
        "voices": "1",
        "pattern": [{ "kern": { "operator": "gt", "value": "@anyAbove" } }]
    }
]
```

## An earlier position

`"#1"` is the first position of the pattern, `"#2"` the second, and so on. The reference reads
the note that position matched, under the key it stands under. A neighbour note that returns to
its pitch:

```json
{
    "feature": "kern",
    "voices": "soprano",
    "pattern": [
        { "kern": "*" },
        { "mint": "2" },
        { "kern.pitch": "#1", "mint": "2" }
    ]
}
```

A position reference can stand wherever a written value can: negated (`"!kern.pitch": "#1"`, a
different pitch), in an OR-list next to written values, and as the `value` of a
[comparison](/docs/patterns#comparisons). The options of the key apply to it as well: with
[`kernIgnoreOctave`](/docs/options#kernignoreoctave), `{ "kern.pitch": "#1" }` is the same pitch
in any register.

Soprano and bass moving apart, the interval between them growing from note to note:

```json
{
    "feature": "kern",
    "voices": "soprano",
    "pattern": [
        { "hint-1": "*" },
        { "hint-1": { "operator": "gt", "value": "#1" }, "!mint": "P1" },
        { "hint-1": { "operator": "gt", "value": "#2" }, "!mint": "P1" }
    ]
}
```

### Naming a position

Instead of counting, a position can be given a name: `{ "as": "$leap" }` names it, and `"$leap"`
reads it. The name `as` only labels the position, it does not search for anything. A leap, not
across a phrase end, answered by a step in the other direction:

```json
{
    "feature": "mint",
    "voices": "soprano",
    "pattern": [
        { "mint": "*", "fermata": false },
        { "as": "$leap", "mint": { "operator": "gt", "value": "3" } },
        { "mint": "2", "!mint.direction": "$leap" }
    ]
}
```

A [`simultaneousWith`](/docs/simultaneous) group has positions and names of its own. It cannot
read the positions of the query's pattern, nor the query those of the group.

### What is read

| Key                                                              | Read                                  |
|------------------------------------------------------------------|---------------------------------------|
| `kern`                                                           | the note with its rhythm: `"4f#"`     |
| `kern.pitch`                                                     | `"f#"`                                |
| `duration`                                                       | `"4."`                                |
| `mint`                                                           | `"-M2"`                               |
| `mint.direction`                                                 | `"-"`, or `"none"` for a unison       |
| `mint.number`                                                    | `"2"`                                 |
| `mint.interval`                                                  | `"M2"`                                |
| `hint-<pair>`, `hint-<voice>`, `hint-@pair`                      | `"M10"`                               |
| `hint-<pair>.number`, `hint-<voice>.number`, `hint-@pair.number` | `"10"`                                |
| `fb`                                                             | `"m6 m3"`                             |
| `fb.numbers`                                                     | `"6 3"`                               |
| `deg`, `metweight`, `fermata`                                    | `"7+"`, `"s"`, `"true"`               |
| `mode`, `key`, `keyDeg`                                          | `"minor"`, `"e"`, `"6"`               |
| `word`, `syl`, `sylpos`, `melisma`                               | the lyrics of the verse being matched |

`phrase` takes no reference: it states the role of a note, a phrase start or end, not a value of
it. A wildcard pair like `hint-*4` takes none either: it stands for several pairs, so there is no
single interval to read.

### Reading another key

After the position, a dot and another key read that key instead: `{ "fb": "#1.hint-14" }` is a
chord with the interval soprano and bass formed at the first position. This works for intervals
and their numbers:

- An interval, from a hint key or `mint.interval`, under a hint key or `fb`.
- A number, from a hint key's `.number` or `mint.number`, under a hint key's `.number` or
  `fb.numbers`.

Under `fb` the interval is folded into the octave; a unison or an octave is no figure there.
A part is read under the same part only: `{ "mint.direction": "#1" }`, not
`{ "mint": "#1.mint.direction" }`.

### Good to know

- A position reads itself or earlier positions, never later ones.
- What is read is the score, not the pattern: where `{ "fb": "6 3" }` at the first position
  matches the chord `m6 P5 m3`, `"#1"` reads `"m6 P5 m3"`.
- Where there is no value to read, the reference does not match: a rest has no pitch, and the
  first note of a voice has no interval into it. A negated reference does match there.
- Lyrics are read in the same verse.
- A `"#"` without a number is a sharp of `kern`: `"#"` and `"##"` are no references.
- A `duration` reference is checked on a single note;
  [`durationAllowSplitNotes`](/docs/options#durationallowsplitnotes) and
  [`durationAllowMergedNotes`](/docs/options#durationallowmergednotes) do not apply to it.

### In `everyPosition`

[`everyPosition`](/docs/patterns#the-same-features-at-every-position) can only hold a reference
every position can read: `"#1"`, or the [name](#naming-a-position) of the first position. All notes
in the key of the first position:

```json
{
    "feature": "deg",
    "voices": "soprano",
    "everyPosition": { "mode": "minor", "key": "#1" },
    "pattern": [
        { "deg": "3" },
        { "deg": "2" },
        { "deg": "1", "phrase": "end" }
    ]
}
```

`as` cannot stand in `everyPosition`.
