---
title: hint
description: Searching by the harmonic interval between a specific pair of voices.
---

`**hint` is Humdrum's [harmonic-interval
representation](https://www.humdrum.org/tool/hint/index.html): a diatonic
interval size with its quality (`M3`, `P5`, `m10`, …). It can also be generated
with humlib's [`fb`
tool](https://doc.verovio.humdrum.org/filter/fb/#interval-quality) via its
`--hint` option. Unlike `fb`'s own default output, which reduces the whole
texture to intervals above the bass, `hint` is computed **per pair of voices**:
one spine for bass/tenor, one for bass/alto, one for tenor/soprano, and so on.



## `hint-<pair>`

`chorale-search` generates one `**hint-<pair>` spine for every unordered pair of
the four voices: `hint-12`, `hint-13`, `hint-14`, `hint-23`, `hint-24`,
`hint-34`. Like `fb`, each of these is a single spine per chorale, not one per
voice, so a lookup against `hint-14` always resolves to the same spine
regardless of which `voices` you searched for. Searching `hint-14` with
`"voices": "tenor"` reads the exact same bass/soprano data as `"voices":
"bass"`.

There's no bare `**hint` feature (unlike `fb`, which does exist as its own
single spine derived the same way): every hint spine is tied to a specific pair,
so `feature: "hint"` or a bare `"hint"` key always matches nothing.



## Token format

A `**hint` token is a single interval: an optional quality letter (`M`, `m`,
`P`, `A`, `d`, …) followed by a diatonic number, e.g. `m3` or `P5`.

The interval is always given as an absolute value, measured from the
lower-numbered voice of the pair up to the higher-numbered voice. It's never
negative, so the interval size alone can't tell you whether the lower-numbered
voice actually sounds below the other at that moment, only how far apart they
are.

Just like `fb`, the quality letter can be omitted to match any quality:

| Pattern value | Matches figure `3` as |
|---------------|------------------------|
| `"M3"`        | only a major 3rd       |
| `"3"`         | any 3rd, any quality   |

A widely spaced pair like bass/soprano routinely produces genuinely compound
intervals (`M10`, `P12`, `M17`, and so on) rather than folding them down to
`M3`/`P5`/`M3` within an octave. See
[`hintReduceCompound`](/docs/options#hintreducecompound) if you want a pattern
value like `"3"` to also match a `10`, `17`, etc.

```json
{
    "feature": "hint-14",
    "voices": "bass",
    "pattern": [
        { "hint-14": "P8", "fermata": true }
    ]
}
```

finds every moment the bass carries a fermata while it's exactly an octave apart
from the soprano.



## `hint-<voice>`

A pattern key can also name a pair relative to whichever voice is currently
being walked, e.g. `hint-2`. Searching `voices: "1234"` with a `hint-2`
constraint resolves the pair separately for each voice being walked: `hint-12`
while walking the bass, `hint-23` while walking the alto, `hint-24` while
walking the soprano.

```json
{
    "feature": "kern",
    "voices": "1234",
    "pattern": [
        { "hint-2": "P5" }
    ]
}
```

`hint-<voice>` only makes sense as a cross-referenced constraint next to another
driving feature (`kern`, `deg`, …), since there's no `hint-2` spine to walk
directly, it's resolved fresh at each onset, relative to whichever voice is
being searched.

`hint-<voice>` is what makes a genuine parallel-motion search possible: both
sides of the pair stay fixed to the same two voices across every position in the
pattern, because one side is the digit you wrote and the other is whichever
voice the search is walking, neither changes from position to position.

```json
{
    "feature": "kern",
    "voices": "alto",
    "pattern": [
        { "hint-2": "P5" },
        { "hint-2": "P5" }
    ]
}
```

finds consecutive perfect 5ths between the alto and the tenor specifically, not
"any voice a 5th above any other voice twice in a row", which a pair wildcard
can't express, since it lets the pair itself vary from one position to the next.



## Wildcard pairs

Either digit (or both) in a `hint-<pair>` key can be `*`, meaning "any pair
matching this digit pattern". `hint-*4` means "hint-14, hint-24, or hint-34: any
voice's interval to the soprano". The position is satisfied if **any** one of
the matching pairs currently has the pattern value, not all of them at once:

```json
{
    "feature": "kern",
    "pattern": [
        { "hint-*4": "M6" }
    ]
}
```

finds every onset where at least one lower voice forms a major 6th with the
soprano, regardless of which voice it is. Unlike `hint-<voice>`, a wildcard pair
is re-evaluated independently at each position, so it can't pin down "the same
two voices" across a multi-position pattern the way `hint-<voice>` does.



## Using it in a pattern

`hint-<pair>` is most useful either as the driving feature (walking that
specific pair's interval as it changes) or as a secondary constraint alongside
`kern`/`deg`/`mint` (checking "what's this specific pair of voices doing when
that melodic thing happens"); `hint-<voice>` is a secondary constraint only.

```json
{
    "feature": "deg",
    "voices": "soprano",
    "pattern": [
        { "deg": "2" },
        { "deg": "1", "hint-14": "P8" }
    ]
}
```

finds a soprano 2-to-1 resolution where the tonic lands exactly an octave above
the bass. See [Patterns](/docs/patterns) for OR-lists, wildcards, multi-feature
positions, and negation, all of which work the same way for `hint` keys as for
any other feature.
