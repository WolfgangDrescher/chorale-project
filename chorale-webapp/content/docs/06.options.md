Query-level fields that don't belong to `pattern` itself: toggles that change
how a match's boundaries or comparisons are computed. They never change *which*
features or values a pattern asks for, only how those asks are judged.

| Option                                                                  | Type                              | Default   | What it does                                                                                              |
|-------------------------------------------------------------------------|-----------------------------------|-----------|-----------------------------------------------------------------------------------------------------------|
| [`mintStartAtPreviousToken`](#mintstartatprevioustoken)                 | `boolean`                         | `false`   | Reports a `mint` match as starting on the note the first interval was measured *from*, one onset earlier. |
| [`mintAllowIntervalComplementation`](#mintallowintervalcomplementation) | `string`/`number` or `array`      | —         | Lets the listed interval numbers also match their complement, so `"-5"` can also match `+4`.              |
| [`fbCompareExactChord`](#fbcompareexactchord)                           | `boolean`                         | `false`   | Requires an `fb` chord to have exactly the figures of the pattern value, with no extras.                  |
| [`kernIgnoreOctave`](#kernignoreoctave)                                 | `boolean`                         | `false`   | Matches a `kern` pitch in every register instead of the one written.                                      |
| [`hintReduceCompound`](#hintreducecompound)                             | `boolean`                         | `false`   | Folds `hint` intervals into one octave before comparing, so `"3"` also matches a 10th.                    |
| [`durationAllowSplitNotes`](#durationallowsplitnotes)                   | `boolean`                         | `false`   | Lets a `duration` also be added up from consecutive repetitions of the same note.                         |
| [`simultaneousAlignment`](#simultaneousalignment)                       | `"start"`, `"end"`, `"start-end"` | `"start"` | Picks which positions of a `simultaneousWith` match must line up with the primary match.                  |

Every one of them can also be set inside a single entry of
[`simultaneousWith`](/docs/simultaneous), overriding the query's own value just
for that group's matching. Leaving one out of a group inherits the query's
top-level value instead.



## `mintStartAtPreviousToken`

**Type:** `boolean` · **Default:** `false`

Only affects searches driven by [`mint`](/docs/features/mint). A `**mint` token
describes the interval *into* a note, so the first onset your pattern checks is
already the second note of the phrase you're matching. The note the interval
starts *from* isn't itself checked by position 0, and by default it's left out
of the reported `startPosition`/`startLine`.

Setting `mintStartAtPreviousToken: true` shifts the reported start back by one
onset, so the match begins on the note the first interval was measured from, not
the note it lands on.

```json
{
    "feature": "mint",
    "voices": "soprano",
    "mintStartAtPreviousToken": true,
    "pattern": [
        { "mint": "-2" },
        { "mint": "-2" }
    ]
}
```

Without the option, a match's `startLine` points at the *second* note of the
descending-2nds run; with it, `startLine` points at the *first* note, one note
earlier, so the highlighted range covers all three notes of the run instead of
just the last two:

::code-group

```vue [without the option]
chorale  feature  voice    start_line  end_line  start_position  end_position
chor029  mint     Soprano  26          30        3               4
chor029  mint     Soprano  30          32        4               5
chor029  mint     Soprano  32          34        5               6
chor029  mint     Soprano  34          36        6               7
chor029  mint     Soprano  46          48        12              13
chor029  mint     Soprano  48          50        13              14
chor029  mint     Soprano  57          60        19              20
chor029  mint     Soprano  60          61        20              21
chor029  mint     Soprano  73          76        27              28
chor029  mint     Soprano  76          78        28              29
chor029  mint     Soprano  78          80        29              30
chor029  mint     Soprano  87          89        34              35
chor029  mint     Soprano  89          90        35              35+1/2
chor029  mint     Soprano  90          92        35+1/2          36
chor029  mint     Soprano  105         107       44              45
chor029  mint     Soprano  107         109       45              46
chor029  mint     Soprano  113         116       48              50
```

```vue [with mintStartAtPreviousToken]
chorale  feature  voice    start_line  end_line  start_position  end_position
chor029  mint     Soprano  25          30        2               4
chor029  mint     Soprano  26          32        3               5
chor029  mint     Soprano  30          34        4               6
chor029  mint     Soprano  32          36        5               7
chor029  mint     Soprano  43          48        11              13
chor029  mint     Soprano  46          50        12              14
chor029  mint     Soprano  56          60        18              20
chor029  mint     Soprano  57          61        19              21
chor029  mint     Soprano  70          76        26              28
chor029  mint     Soprano  73          78        27              29
chor029  mint     Soprano  76          80        28              30
chor029  mint     Soprano  85          89        33              35
chor029  mint     Soprano  87          90        34              35+1/2
chor029  mint     Soprano  89          92        35              36
chor029  mint     Soprano  103         107       43              45
chor029  mint     Soprano  105         109       44              46
chor029  mint     Soprano  110         116       47              50
```

::

**The escape hatch**: the shift is skipped when position `0` of your pattern
explicitly sets `mint` to a wildcard, `{ "mint": "*" }`, so that it doesn't add
one extra step on top of a position you've already accounted for yourself. Any
other position `0` (a specific `mint` value, or no `mint` key at all, e.g. only
checking `duration` or another feature) still gets the shift.

**Rests**: `**mint` measures across rests, from the last note that actually
sounded, and the shifted start follows that same rule. If one or more rests sit
between the first matched interval and the note it was measured from, the start
skips over them to that sounding note rather than landing on a rest. When
nothing sounds earlier in the voice at all, there is nothing to shift back to
and the match keeps its own first onset.



## `mintAllowIntervalComplementation`

**Type:** `string`/`number` or `array` of `strings`/`numbers` · **Default:** *none* (off)

Affects any [`mint`](/docs/features/mint) pattern key, whether `mint` is the
driving feature or a cross-referenced check alongside another one. It lets a
pattern value *also* be satisfied by its **complementary interval**: the
interval that fills the rest of the octave in the opposite direction. A 5th down
and a 4th up land on the same pitch class from the same starting note, an octave
apart, so for many melodic questions they're the same move:

```json
{
    "feature": "mint",
    "voices": "bass",
    "pattern": [
        { "mint": "-5" }
    ],
    "mintAllowIntervalComplementation": ["5"]
}
```

Without the option, this finds only descending 5ths. With it, it also finds
ascending 4ths.

The value is the set of **diatonic numbers** you're opting in, either a single
value or an array. Entries may be written as strings or as plain numbers (`["4",
"5"]` and `[4, 5]` are the same thing), and `"*"` opts in every number at once.
Only simple intervals have a complement within the octave, so entries must be
`1`&ndash;`8` (or `"*"`).

### How a value is complemented

| Component | Complement                                                               |
|-----------|--------------------------------------------------------------------------|
| number    | `9 −` the number: `1`&harr;`8`, `2`&harr;`7`, `3`&harr;`6`, `4`&harr;`5` |
| direction | flipped: `+`&harr;`−` (a value with no sign stays direction-agnostic)    |
| quality   | inverted: `M`&harr;`m`, `A`&harr;`d`, `P` stays `P` (so `AA`&harr;`dd`)  |

So `"-P5"` also matches `+P4`, `"+M2"` also matches `-m7`, and the sign-less
`"5"` (a 5th in either direction) also matches any 4th in either direction.
Quality is inverted properly, which means the option never widens *quality*: a
pattern of `"+M2"` picks up `-m7`, never `-M7`.

### It's the number in your pattern that opts in

An entry opts in every pattern value **written** with that number, not every
value that could complement *to* it. Listing `"5"` makes `{ "mint": "-5" }` also
match a `+4`; it does **not** make `{ "mint": "+4" }` also match a `-5`. To have
it both ways, list both numbers:

```json
{
    "feature": "mint",
    "pattern": [
        { "mint": "+4" }
    ],
    "mintAllowIntervalComplementation": [4, 5]
}
```

This keeps each direction of the shorthand something the query asks for
explicitly, so a pattern position never quietly matches more than the numbers
you listed.

Values with nothing to complement are left alone even under `"*"`: a value
without a diatonic number (`"+"`, `"-"`, a bare quality), a compound interval (a
9th and up), and `mint`'s bracketed first-note marker (e.g. `"[gg]"`) all keep
matching exactly what they matched before. Negation composes as usual: with the
option on, `{ "!mint": "-5" }` excludes both descending 5ths **and** ascending
4ths (see [Negating a feature](/docs/patterns#negating-a-feature)).



## `fbCompareExactChord`

**Type:** `boolean` · **Default:** `false`

Only affects comparisons against [`fb`](/docs/features/fb). By default, a
multi-figure pattern value like `"2 4"` is a **minimum** requirement. It matches
any chord that contains *at least* those figures, so it also matches an actual
chord of `"2 4 6"`. Setting `fbCompareExactChord: true` requires the actual
chord to have **exactly** as many figures as the pattern value, no more:

```json
{
    "feature": "fb",
    "fbCompareExactChord": true,
    "pattern": [
        { "fb": "m6 m3" }
    ]
}
```

With the default (`false`), this also matches a four-note chord that happens to
contain both a minor 6th and a minor 3rd above the bass, alongside other
figures. With `fbCompareExactChord: true`, it only matches chords that are
*exactly* a minor 6th and minor 3rd, nothing else sounding above the bass.



## `kernIgnoreOctave`

**Type:** `boolean` · **Default:** `false`

Affects any `kern` pattern key, whether `kern` is the driving feature or a
cross-referenced check alongside another one. By default, a pitch pattern
value's register must match exactly, so `"G"` only matches a `G` in that exact
octave, not `g`, `GG`, `gg`, or any other octave of the same pitch class.
Setting `kernIgnoreOctave: true` matches that pitch class in **every** register:

```json
{
    "feature": "kern",
    "kernIgnoreOctave": true,
    "pattern": [
        { "kern": "G" }
    ]
}
```

Accidentals always count as part of the pitch regardless of the option: `"G#"`
with `kernIgnoreOctave: true` matches a G♯ in any octave, never a plain G.
Rhythm and fermata components in the same pattern value (e.g. `"4G;"`) are
unaffected and still have to match exactly.



## `hintReduceCompound`

**Type:** `boolean` · **Default:** `false`

Affects any [`hint-<pair>`/`hint-<voice>`](/docs/features/hint) pattern key. By
default, a pattern value's interval size must match exactly, so `"3"` only
matches a genuine 3rd, not a compound 3rd (a 10th, a 17th, …). Setting
`hintReduceCompound: true` folds both the pattern value and the actual interval
down to within an octave before comparing. A unison and an octave stay distinct
from each other. So `"3"` also matches a 10th:

```json
{
    "feature": "hint-14",
    "hintReduceCompound": true,
    "pattern": [
        { "hint-14": "M3" }
    ]
}
```

Without the option, this only matches an actual major 3rd between bass and
soprano. With it, it also matches a major 10th or major 17th between them, since
bass/soprano is wide enough that the interval is routinely compound in the raw
data (see [hint](/docs/features/hint#token-format)).



## `durationAllowSplitNotes`

**Type:** `boolean` · **Default:** `false`

Affects any `duration` pattern key. By default a position's `duration` is the
sounding duration of the **one** onset that position is checked against, so a
pattern asking for a half note only finds notes actually written as half notes.
A chorale often spells the same musical note out as repeated shorter notes
instead and those repetitions are missed.

Setting `durationAllowSplitNotes: true` lets such a position instead be
satisfied by a **run of consecutive onsets that re-articulate one and the same
note**, whose durations add up to one of the position's allowed values:

```json
{
    "feature": "kern",
    "voices": "alto",
    "durationAllowSplitNotes": true,
    "pattern": [
        { "kern": "d", "duration": "2" }
    ]
}
```

In chor001 the alto's opening `d` is a quarter-note upbeat re-attacked as
another quarter in bar 1; A half note's worth of `d`, never written as one.
Without the option only the genuine half notes are found; with it, the split one
joins them.


### What counts as the same note

A run may only grow across onsets that re-attack the note it started on, which
depends on the driving feature:

| Driving feature | A run continues while                                                                     |
|-----------------|-------------------------------------------------------------------------------------------|
| `kern`          | the pitch stays the same (rhythm, beams, slurs and ties are ignored)                      |
| `mint`          | the interval into the onset is a perfect unison (`P1`) — how `**mint` writes a repetition |
| anything else   | the spine repeats its own token (`deg`, `fb`, `metweight`, `hint-<pair>`)                 |

A run also stops as soon as the sum **overshoots** every allowed value: with
`"duration": "2"`, three repeated quarters are a dotted half and match nothing,
while the first two of them are a match.


### The rest of the position

Only `duration` is summed. Every **other** key of the same position is checked
on **every** onset of the run, so a `deg`, `fb` or `hint-<pair>` constraint has
to hold for the whole logical note, not just its first onset; a repetition under
changing harmony fails a harmonic constraint that the change breaks. Two keys
are treated specially:

- The **driving feature's own key** is checked on the run's first onset only.
  What follows is a re-attack of that same note, which is what the table above
  already vouches for.
- **`fermata`** is checked on the run's **last** onset, the one that closes the
  note off, since that is where a chorale writes the fermata.

A run consumes as many onsets as it needs, and the pattern simply carries on
from the one after it. So positions after a split position line up with the
notes that actually follow the run, and a match's `endLine`/`endPosition` report
the last onset it consumed.



## `simultaneousAlignment`

**Type:** `string` · **Default:** `"start"` · **One of:** `"start"`, `"end"`, `"start-end"`

Only relevant with [`simultaneousWith`](/docs/simultaneous). Picks which of a
group's own match positions must line up with the primary match's:

- `"start"` &mdash; the group's match must **start** where the primary match starts.
- `"end"` &mdash; the group's match must **end** where the primary match ends.
- `"start-end"` &mdash; both at once, i.e. the two matches run for the exact same duration.

```json
{
    "feature": "deg",
    "voices": "soprano",
    "pattern": [
        { "deg": "3" },
        { "deg": "2" },
        { "deg": "1", "fermata": true }
    ],
    "simultaneousWith": [
        {
            "feature": "deg",
            "voices": "bass",
            "pattern": [
                { "deg": "5" },
                { "deg": "5" },
                { "deg": "1" }
            ]
        }
    ],
    "simultaneousAlignment": "start-end"
}
```

Set at the top level it applies to every group; a single group can override it
with its own `simultaneousAlignment` (see [simultaneousWith](/docs/simultaneous)).
